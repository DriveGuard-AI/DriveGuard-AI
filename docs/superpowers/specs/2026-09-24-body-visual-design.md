# Frozen RGB body-distraction experiment

The user approved the proposed three-way comparison. A is the existing gap80 checkpoint, frozen. B is a small binary distraction head over frozen RGB features. C uses the same RGB head plus frozen gap80 feature context. Only the body distraction task is trained in this experiment; other tasks continue to belong to the unchanged reference model. This is a feature-sufficiency experiment, not a production replacement.

## Contracts

- Reuse the original immutable DMD v3 manifest, split and endpoint labels. Validate source videos against original cache provenance. Never require a successful MediaPipe detection to obtain an RGB image.
- Use each record's existing driver_roi, including full frame when that is the recorded ROI. Preserve the entire ROI by letterboxing to 224x224, BGR to RGB and ImageNet mean/std normalization. No guessed per-video head crops.
- Sample exactly grid slots `25*n+12` and `25*n+24` that exist. For a 100-slot window starting at a multiple of 25, take offsets `[12,24,37,49,62,74,87,99]`. This gives eight causal frames with the final one at the label slot. Use original PTS selection and reject misalignment; stale frames (>80 ms) have visual mask false and zero features.
- Encoder: ResNet18 compatible with torchvision ImageNet V1 state_dict, 512-D average-pooled representation. Use explicit local weights plus SHA256, no implicit random/pretrained fallback. Decoder/encoder batch memory must be bounded. Each video has immutable feature NPY files, checksums and a success marker written last; completed videos can be reused after validation.
- Cache schema `driveguard-visual-cache-v1`: top-level status, manifest_sha256 (file bytes), encoder metadata, records list. Each record entry includes record_id, split/view/subject_id/recording_id/subset, original slots, sample_count, directory, arrays {embeddings,slot_indices,source_pts_ms,valid}, sha256 matching array keys, and source provenance. Embeddings float32 [K,512], grid indices int64 [K], PTS int64 [K], valid bool [K]. Relative contained paths only.
- Extraction callable `extract(manifest, data_root, dataset_root, weights, weights_sha256, output_dir, backend='cpu', device_index=0, batch_size=32, continue_run=False)`; outputs all body train/val/test records (no label-based selection). No pretrained asset download inside extraction.
- Preparation freezes a trusted gap80 checkpoint, verifies its original corpus fingerprint and the visual-cache identity, computes train-only visual/context normalization and per-window cached context. Context concatenates masked four original group embeddings, masked H embedding, 8 original quality values + 2 H qualities, 5 eligibility flags and distraction logit: `5*projection_dim+16` dimensions. A prediction reference is taken from the actual original model output, not reconstructed logits.
- Prepared dataset protocol: attributes `visual_dim=512`, `context_dim`, `__len__`, `__getitem__ -> ({visual:float32[8,512],context:float32[C],visual_mask:bool[8]}, target:float32 scalar, known:bool scalar)`; `metadata(index)` returns original record/window keys plus `baseline_logit`, `baseline_available`, `h_eligible`. Features loaded by bounded mmap. Visual availability requires all eight fresh frames. Unknown labels are never supervised.
- Training API `train_probe(train_dataset,val_dataset,mode,settings,output_dir,provenance,resume=None)` in training/visual/train.py. Modes visual/fusion. Settings contain epochs,batch_size,seed,learning_rate,weight_decay,gradient_clip_norm,hidden_dim,dropout,backend,device_index. Model `VisualProbe(visual_dim,context_dim,hidden_dim=64,dropout=.1,mode='visual')`, forward(visual,context,visual_mask) returns dict(logits:[B],available:[B]). Visual-only must be independent of context, unavailable samples excluded from loss but retained in reporting.
- Model reload helper `load_probe(path,backend='cpu',device_index=0)` returns eval model,payload. Save best/last integrity sidecars, full history and CPU/loader/device RNG for exact epoch resume; provenance mismatches rejected. Best selected by binary validation BCE, different from reference joint-loss checkpoint selection and explicitly labeled.
- Compare A/B/C on exactly the same body windows at threshold .5, include unavailable-positive denominators and fixed baseline-H cohorts, per-subject/record breakdowns. Train selection is on validation only; no held-out claims. PR operating-point exploration is diagnostic, not automatic deployment.

## Validation

Test causal sample indices, source PTS and cache corruption, label/split identity, bounded decoding and no MediaPipe imports, frozen backbone preprocessing and weight loading, no future windows, train-only normalization, visual-only context independence, unavailable supervision, exact resume and full synthetic three-way run. Run a real pretrained encoder smoke if local dependencies/weights permit; report the boundary honestly otherwise.
