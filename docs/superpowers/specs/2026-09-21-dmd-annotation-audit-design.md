# DMD 全量标注审计设计

2026-09-21 · shadow · 状态：用户已批准编码，审计工具已实现；服务器全量扫描待执行。

## 目标与范围

提供仓库内的固定命令，扫描服务器上的 DMD 原始标注，生成录制配对、标签覆盖、被试分布及同步信息报告。替代临时 test.sh 数据检查，不安装依赖、不解码视频、不启动训练、不改写数据集。

这是正式数据准备的第一步，不是完整的标签转换器。报告用于决定标签映射和两份被试划分；不能作为视频完整性、标签正确性或训练可用性的验收证明。

## 已知事实及来源

以下为用户提供的文件清单及本机实际解析的标注样例，不代表已访问服务器全部数据：

- 10 位被试：1、5、6、7、9、10、13、14、23、29；三个子集都有这 10 位被试。
- distraction 35 段、drowsiness 12 段、gaze 11 段，共 58 段录制、289 个文件。一个 session 目录可能包含多段录制。
- 当前 drowsiness 文件清单没有 hands 视频；其标注仍可能声明 hands_camera。记录“声明但缺失”，不要求重新下载，也不伪造观测。
- distraction 样例包含喝水、安全驾驶、操作收音机、侧向取物、交谈、换挡及道路注视状态。物体存在标签不能替代使用手机的动作标签。
- drowsiness 样例包含眼睛开闭及过渡、眨眼和打哈欠，没有直接的疲劳/清醒分类。
- gaze 样例包含注视区域和 not_valid；hands 样例包含握方向盘状态、控制权过渡和手部运动。gaze/hands 样例属于同一录制，但有各自标签覆盖。
- 样例采用 OpenLABEL 1.0.0，区间使用 frame_start/frame_end；摄像头存在 frame_shift。偏移方向及解码时间映射不在本轮擅自推断。
- drowsiness 样例标注 0～5480，而 face_camera 声明 total_frames=5480。报告数量差异，不修改末帧或复制标签。
- 用户回传 NPU 验证：Ascend910B3，torch 2.7.1+cpu、torch_npu 2.7.1.post4；合成数据 10 轮、30 次更新，恢复后增加 15 次更新，52 个状态张量变化，权重重载 NPU 推理通过。不是本机执行记录或真实 DMD 成绩。

## 方案选择

采用纯 Python 标准库的独立审计工具。与“直接批量提取全部视频”相比，先得到全量标签依据，避免为无监督或错误映射的任务消耗提取时间；与“继续手工复制 JSON”相比，可以复用且覆盖全部文件。

不引入数据库、Web 界面、额外依赖或新的严格审批门禁。测试仅覆盖解析正确性，数据警告不一律阻止后续开发。

## 输入、输出与命令

审计入口（已实现）：

```bash
/opt/buildtools/Python-3.11.4/bin/python3 -S -m training.dmd.audit \
  --dataset-root /mnt/workspace/DriveGuard-AI/Dataset \
  --output-dir /mnt/workspace/DriveGuard-AI/runs/dmd-audit-001
```

- 输入：本地 Dataset 根目录；识别 distraction/drowsiness/gaze 的 dmd/group/subject/session 布局。报告无法识别的布局，不静默遗漏。
- 输出目录必须不存在，避免覆盖历史审计。
- audit.json：机器可读的被试、录制、标签、文件问题、同步声明和输入标注 SHA-256。
- audit.md：人可读摘要及问题清单，不导出年龄、性别等与本次训练准备无关的个人属性。
- 不生成 targets、label_masks、正式训练 manifest 或任何真实训练成绩。

## 解析规则

1. 逐文件解析，限制内存为单份 JSON 与紧凑摘要，不同时加载全部标注。不导入 torch、torch_npu、MediaPipe、YOLOX。
2. 按完整录制名前缀配对文件；同录制的 gaze/hands 标注合并到录制清单，但按标注来源分别统计，避免重复计算录制数量。
3. 使用现有严格 JSON 读取逻辑，拒绝重复键及非有限值；报告空文件、非法结构、反向区间、非整数帧号和未定义的动作引用。
4. 通过 actions 中的 type 解析语义；动作 ID 只在该文件中有效，不能跨文件硬编码 ID 含义。
5. 报告每个原始 action type 的区间数量及合并后的覆盖帧数。重叠区间不重复计数；不同标签轴允许并存，不能把所有重叠当作冲突。
6. 记录 not_valid、unclassified 等原始类型及覆盖；缺少标签保留未知。首轮不把原始类型自动映射成四任务正负标签。
7. 顶层区间、逐帧动作引用与动作区间间的差异输出诊断，不静默选择一种作为最终训练真值。
8. 每条流记录 uri、total_frames、frame_shift 及配套文件存在性；依据本地录制配对，不打开标注中的任意外部 URI。报告越出数据根目录的引用，且不跟随逃逸符号链接。
9. 区分“声明帧数”与“实际解码帧数”；本轮只采集前者。不把帧数除以固定 FPS 得出精确标签时刻。
10. 按 subset、全局被试 ID、录制及标签类型汇总。主体 ID 跨三个子集保持一致；报告同一编号的组别/标注身份矛盾。

## 报告与异常处理

- 单个坏文件记录错误后继续扫描其余文件，保留可用证据。
- 完整扫描无解析/结构错误返回 0；有错误但已写出报告返回 2；输入根目录或输出目录不可用时返回 2 并说明原因。
- 缺少可选视角、帧数声明差异、未知标签类型属于可见警告，不自动改动原数据，不笼统判定整批数据不可用。
- 提供扫描进度，明确这不是视频推理任务。

## 数据划分与后续衔接

遵循用户要求只保留两份数据，目标为 8 位被试训练、2 位被试留出评估。当前训练器使用 val 选择 best.pt，故留出集在训练 manifest 内使用 val；不额外分出 test，也不称其为独立最终测试。

本轮不硬编码两位留出者，也不按模型跑分挑人。全量标签覆盖确认后固定名单，保证同一被试的全部录制、子集和视角归于同一集合。原始标签覆盖不等于特征窗口可用的正负监督，转换后仍需现有训练器的覆盖检查。

后续工作顺序：确定任务标签语义与同步规则 → 固定被试划分 → 批量特征及标签转换 → 生成 v2 manifest → 启动已有 NPU 训练入口。疲劳代理监督、gaze 与业务分心的映射、跨视角融合均不在本轮默默决定。
